# Decoding Lab

An independent, local probability-printing workbench. It teaches decoding **after
logits**, not neural-network training or chatbot behavior. All sentences are
original micro-corpora written for this project. Nothing is fetched, uploaded,
persisted, or generated by a hosted service.

## Files and extension points

- `data.ts`: the complete original corpora, meaningful starting contexts, and
  three repeatable presets. Repetitions are observations, not display shortcuts.
  Presets always select the printshop, context `the`, seed `42`.
- `model.ts`: pure tokenization, fitted bigram counts, inventory, and logit source.
  Lowercase ASCII words (with internal apostrophes) and `. , ! ? ; :` are tokens.
  Each line starts at `START` and ends with an appended `END`. Lines do not join.
- `engine.ts`: pure stable softmax, filtering, explicit argmax, seeded selection,
  immutable generation history, EOS handling, reset, and RNG-restoring rewind.
- `graphics.ts`: accessible probability/count tables and cumulative-draw strips.
  Data bars are actual probabilities on a shared 0–100% scale, never decorative
  rankings. Pruned tokens remain visible.
- `ui.ts`: layout and escaped output/history/receipt markup.
- `index.ts`: mount, controls, in-memory comparison proof, and lifecycle.
- `style.css`: all rules are scoped to `.project-decoding-lab`.
- `manifest.json`: project discovery only; no shared registry modifications.

To add a corpus, provide original short lines and starting-context choices in
`CORPORA`. Keep its token inventory small enough to read in full. Choose an
`unknown` token absent from that corpus to demonstrate zero-count contexts.
Counts are fitted on selection; changing models or any decoding setting starts a
fresh run. The count-row inspector and recorded-step inspector are read-only.
Pinned proofs intentionally keep their own corpus, context, settings and seed.

## Actual mathematics and policy

With smoothing α = 0.25, `z(t) = ln(c(previous, t) + α)`. Its base softmax is
`(c + α) / (N + αV)`. These are genuinely **fitted counts**, not neural or
pretrained LLM logits. Subtracting the shared `ln(N + αV)` produces equivalent
log-probability logits.

For positive temperature, use `exp((z − max z) / T)`, normalized. Sort by score,
breaking ties by the fixed inventory order (punctuation, lexically sorted words,
then END). Keep top-k positive weights and renormalize. On that post-k
distribution, retain the smallest descending prefix whose mass reaches top-p;
renormalize again. A categorical draw traverses these surviving tokens in the
same order. `k = 0` means all; `p = 1` keeps all positive candidates; `p = 0`
keeps one. Filtering never leaves an empty distribution.

`T = 0` or the Greedy policy selects the first argmax with probability 1 and
entropy 0. It bypasses filtering and consumes **no** random number. This is an
explicit UI convention, not division by zero. The base distribution stays visible
for comparison. Entropy, per-token log probability, and cumulative log probability
use natural logarithms (nats); they do not measure correctness or quality.

Mulberry32 uses an explicit unsigned 32-bit state. Each sampled step records the
state before/after, uniform draw, CDF interval, count source, distributions and
chosen probability. Backtracking restores that exact state and context; reset
restores the selected seed. A one-candidate **sampled** distribution still consumes
one draw, unlike the explicit greedy policy.

## Bounds and honest limitations

- UI: two eight-line corpora; each has 11 possible output tokens. Only the previous
  token is used for prediction. Unknown contexts receive a uniform smoothed base.
- Temperature: 0–4 (slider step 0.05); top-p: 0–1 (step 0.01); top-k: all or 1–V;
  seeds: integers 0–4,294,967,295.
- Generation: at most 24 generated tokens including END, at most 5 per button
  press. No autoplay or timers. A punctuation full stop does not itself terminate
  generation. The 24-token safety stop is labeled separately from actual END.
- Fitting: 1–64 nonempty lines, 240 characters per line, 2,048 text tokens,
  64 output tokens including END. The pure fitter permits α in [0.000001, 100].
  Initial contexts are bounded to 160 characters / 32 tokens.
- Calculations use JavaScript doubles. Shifted softmax prevents overflow; very
  small weights can underflow to zero. Negative-infinity logits are allowed as
  zero-mass candidates; NaN, positive infinity, empty/all-masked input and invalid
  settings are rejected. Seeded draws have 2⁻³² resolution; decimal readouts are
  rounded while calculations and history retain full precision.
- Recombined lines can be off-corpus or nonsensical. The model cannot invent
  vocabulary, interpret instructions, converse, reason, or provide factual
  answers. Common LLM sampling mechanisms are illustrated without implying that
  this count model is a neural LLM.

All events use `page.signal`; cleanup releases comparison state and guards the
imperative reset. There are no observers, animation frames, audio, storage, or
timers. Layout works at 375px with native keyboard controls and no animation,
including reduced-motion mode.

## Focused verification

```sh
npm test -- tests/series/decoding-lab.spec.ts
```

Three tests cover fitted counts/normalization, filtering/temperature/RNG/EOS
boundaries, and browser output/receipts/replay/reset/comparison/mobile keyboard
behavior. Screenshots belong only in Playwright's per-run output directory.
