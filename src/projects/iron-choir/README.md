# 铁穹回声

原创中文机甲远征与战争编年角色扮演游戏。环轨穹城的旧防御网开始用失踪驾驶员的声音唱歌；第九远征队必须查明被无限续写的授权，并为命令写下结束时间。人物、机体、阵营、故事与程序化图像均为独立创作，不改编既有动画。

## 内容与完整流程

六名反复登场的原创人物拥有独立肖像、传记、目标、缺陷与关系：沈砚、罗烬、叶缄、林簿、乔砺、第零声部。三名驾驶员分别操纵承重步机「砧鹭」、索道轻机「纸隼」、织讯工程机「缄灯」；叶缄通过档案井支线加入。机库允许将任意已招募驾驶员设为主控，其他驾驶员由模型协同。

十处可抵达场景贯通三幕、六场不同目标的远征：雨闸清剿、盐滩救援、水泵坚守、断桥护运、墓园还名、冠冕接驳。六项主线与七项支线共十三项任务。五段一次性抉择改变信任、招募、图纸、侧路、真相和终局资格，不是装饰性对话。中文故事集中于 `story.ts`，正文超过五千汉字。

完整循环是 **探索与交谈 → 制造及配装 → 出征 → 截获敌方意图 → 主控行动 → 代理协同与回合结算 → 战利品核对 → 修复、升级与下一幕 → 签署终局**。已经领取奖励的任务不能重刷。三种结局为「共同执笔」「归还寂静」「有限守夜」，各有明确前置条件与独立尾声。

队长失能、民用目标被毁或错过撤离窗口都会真实失败。失败没有战利品或经验；支付三废料救援并修复全队，物资不足时可登记四废料债，由下一次战利品优先偿还。可在任何时候明确重启，也可导出当前合法战记后再开始。

## 操作

机库的「整备机库」负责制造、主武器、核心、战术外挂、修复和成长技能。独有部件一次制造、单机装备；换回原装或拆下外挂后才能转交。装备不会恢复结构。废料、修复匣、记忆线圈与陶铠共享一百二十单位仓容，每类最多六十。升级采用六级曲线，每升一级获得一个技能点，五项成长技能不可重复学习。

战斗时，点选三维场景只选择目标或格点；行动下拉框列出当前所有合法选项，再按「执行所选行动」确认。方向键选择格点，回车执行；空格截获意图或协同结算，Ｇ架盾，Ｖ排热，Ｑ／Ｅ旋转，Ｔ俯视，Ｊ打开战记。原生对话框打开时停用所有世界快捷键。触屏可用同一行动框，或「战术表」中的列、行选择器与二维格点。

所有镜头、阅读、检查与选择操作免费，不产生世界指令。三维拾取、路径、射程和掩体使用相同坐标与实体盒。硬墙挡住传感器射线，低掩体遮住腰部而不遮住传感器时减伤三。射程使用带地形高度的三维欧氏距离；单步可攀高差为零点三六。没有命中率投骰，也没有显示一套几何、实际使用另一套规则。

每轮二行动点。行动有明确能量和热成本，超预算不能提交。原装射击耗一行动、二能量、三热；齐射耗二行动、四能量、多二热并增加四伤害。每轮恢复四能量、至少冷却三、回复一护盾；排热另减五热、回三能量。立壁、远针、缝合与中继外挂提供不同角色职责。护盾先吸收伤害，剩余部分才影响结构。

## 有界代理与隐私

需要支持原生函数工具的兼容接口，通过共享中文模型控制台配置。页面载入、刷新、存档恢复及查看镜头均不会请求模型。没有离线假代理，没有模型直接授予奖励、经验或伤害。

每一轮最多两个**主动发起的代理回合**，而非每步或每帧调用：

1. 旧网指挥员只收到当前可见遥测和各自职责，在玩家决定本轮行动之前锁定守机意图。守闸者守终端，逐迹者追踪暴露目标，凿井者优先攻击可见民用设施。请求中没有玩家未来动作、草稿或未公开目标。
2. 玩家执行主控动作后，同伴收到公开战局、已锁定敌方意图和公开协同目标。沈砚保护、罗烬远射、叶缄修复与接驳。模型只为每台存活代理机体选择一个有限合法选项。

一个代理回合由共享客户端限制为最多两次请求、每次最多一千五百三十六输出令牌、总限时六十秒；第二次仅用于修正非法计划。拒绝未知字段、单位越权、错误轮次、重复单位、碰撞落点与不存在的动作。中文公开意图经过转义显示，不请求或展示私有推理链。

敌方射击锁定其预告时的坐标，后续不会偷偷追随玩家移动。执行顺序固定为同伴、敌方、回合恢复。前一个动作使目标被击毁或路径失效时，后续依赖动作取消且不消耗。锁定射击被玩家躲开则按原坐标落空，仍产生其合法射击成本。网络失败、无效计划、取消和过期结果不产生新游戏消耗；之前已经独立确认的玩家动作保留。

共享控制台以世界版本进行同步提交门控，先用 `session.preview` 校验，再 `dispatch`。重启与导入都取消待定计划。共享笔记本自动保存种子与合法指令，原生导入在草稿里重演全部动作后才原子替换；不信任存档状态对象。正常全战役低于三百条指令，共享回放预算六百。连接密钥不进入战记。

## 文件与渲染生命周期

| 文件 | 职责 |
| --- | --- |
| `data.ts`、`story.ts` | 可编辑的原创建制、经济、任务、角色、插叙与结局 |
| `spatialmath.ts` | 无界面依赖的三维距离、线段盒相交、地形与路径 |
| `engine.ts` | 纯权威状态机、机械行动、奖励、成长、恢复和回放解析 |
| `agent.ts` | 无界面、无样式依赖的严格原生工具、角色观察与烟测 |
| `art.ts`、`render.ts` | 原创程序机体、肖像、立体地形、射线拾取与按需绘制 |
| `index.ts`、`style.css` | 中文工作区、原生对话框、共享模型控制台与笔记本 |
| `manifest.json` | 独立页面注册 |

三维渲染使用已有 Three.js，不增加依赖。白陶、石墨、冷蓝检修光与信号橙形成统一视觉。没有后期效果链、持续动画或音频；镜头不会自动摇晃。像素倍率封顶一点四，只在状态、选择、镜头或容器尺寸变化时申请单次绘制。销毁时释放全部几何、材质、纹理、绘图上下文、事件、尺寸观察器与待执行绘制。无法建立三维上下文时明确提示，二维战术操作仍使用同一纯几何规则。

根工作区使用实际视口高度与可收缩网格；长内容仅在有界指挥台和原生对话框内滚动，不通过隐藏文档溢出来掩盖控件。主标题持续可见，底部模型状态和取消入口可达，并避开集合浮动菜单。

## 专属用例与真实模型入口

`tests/rpg-games/iron-choir.spec.ts` 使用仓库已有 Playwright 与 `tests/helpers/agent-fixtures.ts`，经真实原生客户端接口拦截测试响应。覆盖完整合法界面战役、制造与成长、十三任务、三种已赢得结局、实际失能与恢复、几何、经济、热与行动顺序、策略差异、网络与畸形结果、取消、回放和五种视口。没有向浏览器注入胜利状态，也没有生产夹具代码。

纯 `agent.ts` 导出 `smokeCase()`，返回 `{ request, verify }`。它请求真正的开场敌方机械决策，验证两台守机的合法公开预告，而不是让模型只写旁白。真实模型请求留给统一发布流程串行执行；本项目开发不调用真实模型。
