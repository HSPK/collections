# Phaser 轻玩法：桌面 Agent 游戏

这组游戏优先服务桌面浏览器的键盘和鼠标，不提供手机触控操作层。
剧情短、规则少，角色策略在局间或明确回合中生成，局内即时操作不会
等待模型。使用自己的 OpenAI 兼容工具模型连接，合集不提供共享密钥。

## 五种玩法

| 游戏 | 最主要的操作 | Agent 的职责 |
| --- | --- | --- |
| 猫咪借位 | 移动与交换展品的位置 | 选择可验证的守卫巡查策略 |
| 弹珠外交 | 瞄准、发射、利用反弹 | 在开球前安排合法球台防守 |
| 梦境分拣局 | 向左或向右分拣 | 选择下一波规则与包裹节奏 |
| 云朵合伙人 | 滑动云朵、合成与降雨 | 选择有限的风向、播云和协助行动 |
| 纸上守夜 | 切换灯路、把握照明时机 | 安排有预告、有预算的纸影波次 |

先在游戏中打开「模型」配置连接，再主动开始局程。计分、碰撞、
资源、胜负和进度由游戏规则决定；模型没有任意发奖励或改分的权限。
连接方式参见[中文说明](rpg-guide.zh-CN.md)与[完整接口说明](model-connections.md)。

## 生产架构与实际边界

使用精确锁定的 Phaser 4.2.1，而不是给旧 Canvas 页面包一个空引擎。
每款游戏有独立 Phaser 场景、对象、纹理、输入和表现逻辑。通用适配层
管理缩放、模态暂停、标签页隐藏、动态偏好和销毁，不重复创建渲染循环。

规则、关卡、代理与场景分开维护。即时玩法按固定逻辑步运行，保存有界
输入记录，再由同一引擎重算结果，而不是相信导入文件中的分数。
回放校验、模型请求的过期保护和局间保存复用现有公共模块。

默认工作预算是逻辑画面 960×640、至多 200 个活动显示对象、64 个纹理
和 32 个并行动画。具体游戏的 README 记录自身资源上限及例外。
对象、特效和纹理需要复用，暂停与重开不能持续积累资源。
帧率取决于浏览器、硬件和场景，预算不是所有设备上的帧率保证。

「按生产标准组织」不等于已经具备商业服务的所有能力。这些仍是可独立
部署的单机网页游戏：没有运营级账户、支付、多人权威服务器或反作弊承诺。
若要上线付费或竞争排名，应另行建立服务端存档、计分、认证与运营监控。
浏览器代码与本地回放可查看，不是安全隔离的秘密世界。

## 作者工作流

在每个项目目录中，关卡数据、纯规则、代理工具、Phaser 场景和 DOM 页面
具有独立职责。先改可验证规则和可编辑数据，再连接画面；规则变更需考虑
存档版本，旧回放不能悄悄变成新的成绩。

日常命令：

```sh
npm run dev
npm run build
npm test -- tests/phaser-games/cat-shift.spec.ts
```

`src/core/phaser/README.md` 定义共享场景与固定步进接口。
自动化流程使用原生工具格式的模型夹具，不在 CI 中调用真实模型。
真实模型验收需要显式启用 `tests/agent-models.spec.ts`，并承担服务商费用。

Phaser 的 MIT 许可随网站保留于
`public/third-party/phaser-LICENSE.txt`。游戏画面与故事为项目原创，
不依赖外部字体、远程贴图或官方演示 CDN。
